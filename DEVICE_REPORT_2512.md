# Отчёт: SmartBox Giga / OpenWrt 25.12.6

По сообщению пользователя из темы 4PDA обнаружены воспроизводимые ошибки кода. Аппаратная проверка именно SmartBox Giga не проводилась.

## Температура

Мобильный экран содержал постоянные значения 61.3/58/58 °C и названия конкретных MediaTek-чипов. При ошибке чтения они оставались на экране. Теперь перечисляются реальные thermal/hwmon-файлы и подписи драйверов, значения обновляются, ошибки очищают прошлые показания. Отсутствующий датчик показывается как недоступный; приложение не может создать датчик, которого не предоставляет прошивка.

## Установка VPN-пакетов

Список пакетов для обнаружения включал альтернативные реализации и необязательные LuCI-панели. Установка всего списка одновременно приводила к конфликтам/отсутствующим пакетам. Новый установщик выбирает один доступный вариант каждой обязательной группы в подключённых репозиториях, определяет apk/opkg по наличию команды, обновляет индексы и подтверждает установленные пакеты. Версия OpenWrt сама по себе не определяет менеджер пакетов.

Мобильная установка запускается в фоне, чтобы короткий rpcd/HTTP-таймаут не прерывал ожидание пакетного менеджера. Приложение опрашивает результат и показывает копируемый журнал. Потеря связи или истечение ожидания не считаются успешной установкой; операция может ещё идти. Windows использует тот же shell-установщик и проверяет фактический код завершения, не слова «Installing» в выводе.

Пакеты устанавливаются **на роутере**, а не на телефоне. Для подключения нужен профиль/сервер или подписка. Отсутствующие сторонние пакеты требуют совместимого репозитория; несовместимые модули ядра — пакетов именно для сборки прошивки. Приложение не отключает проверки подписей и не принуждает установку несовместимых пакетов.

## Если ошибка остаётся

Нужны версия и платформа программы, название выбранного протокола и текст результата установки. Дополнительно полезны модель/версия/архитектура из `ubus call system board`, наличие `apk`/`opkg` и факт существования thermal/hwmon-датчиков. Не публикуйте пароли, ключи, токены и URL подписок. По одному скриншоту сообщения нельзя доказать единственную причину отказа именно этого роутера.

Windows EXE находятся в отдельном [Windows Releases](https://github.com/RichkovGit/OpenWrtStudio/releases/latest), в блоке Assets. APK и Linux — в [Releases приложения](https://github.com/RichkovGit/OpenWrtStudio-Mobile/releases/latest).

## Повторный отчёт об отказе RPC — 26.10.2026

На скриншоте терминал получает отказ `file.exec`. Это не запрос root на Android. Сессия LuCI может иметь доступ к данным и UCI, но не иметь права выполнять произвольную команду. Проверяются два уровня: метод ubus `file.exec` и конкретный путь/команда (для скриптов Studio — `/bin/sh`). Даже имя пользователя root само по себе не доказывает разрешение текущей rpcd-сессии; по одному скриншоту нельзя отличить ограниченную ACL, другую учётную запись и проблему сессии.

- Температура: при отказе shell приложение пробует только `file.list/read` в thermal/hwmon. Имена каталогов и файлов ограничены шаблонами датчиков. Используются только уже выданные разрешения; ACL не меняются. Доступный датчик читается даже при отказе другого. Если чтение запрещено, отказ не превращается в сообщение об отсутствии датчиков или выдуманную температуру.
- Терминал и установщик показывают объяснение отказа по-русски/английски. Терминал не принимает пустой/повреждённый RPC-ответ за exit=0. Структурированная ошибка сохраняется, а запущенная ранее фоновая установка не объявляется остановленной из-за потери прав при опросе.
- Новый кандидат собирается с applicationId `com.cogwheel.LuCIMobile.permissiontest`. Он может стоять рядом и со стабильным приложением, и с ранее выданным `upstreamtest` с другой debug-подписью. Данные этих приложений не удаляются. APK не выдаёт серверные права и не гарантирует работоспособность функций, заблокированных ACL роутера.

Чтобы выяснить состояние конкретного SmartBox, нужен ответ, под какой учётной записью выполнен вход и помогает ли повторный вход. Для полной работы команд потребуется разрешение администратора на стороне роутера или отдельный согласованный административный транспорт. Не выдавайте всем пользователям wildcard ACL и не публикуйте пароль/идентификатор сессии. Изменение прав на чужом роутере приложением не выполняется.

Основание: [ACL штатного LuCI](https://github.com/openwrt/luci/blob/openwrt-25.12/modules/luci-base/root/usr/share/rpcd/acl.d/luci-base.json), [проверка исполняемой команды rpcd](https://github.com/openwrt/rpcd/blob/master/file.c). Модель/датчики/ACL самого SmartBox пока не проверены на устройстве.

Проверка 26.10.2026 в Windows: flutter analyze --fatal-infos — без замечаний; 598 тестов прошли, 2 пропущены (opt-in live-router и Linux-only процесс). ARM64 debug APK собран; пакет com.cogwheel.LuCIMobile.permissiontest проверен через aapt. Телефон сейчас не виден в ADB; проверка на устройстве и на SmartBox не выполнена. Настройки роутера не менялись.
